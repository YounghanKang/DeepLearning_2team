# 7-3 자체 데이터 수집 프로토콜 기술 검토

가이드라인 7-3 조건별 기술적 구현 가능 여부를 분석한 문서입니다.

---

## 조명 조건

| 조건 | 가능 여부 | 비고 |
|------|----------|------|
| 형광등 | ✅ 완전 가능 | 기본 조건 |
| 어두움 | 🟡 부분 가능 | MediaPipe 신뢰도 0.5 미만 시 `None` 반환. `eye_extractor.py`에 밝기 보정 없음 → 수집 스크립트에서 CLAHE 전처리 추가 필요 |
| 역광 | 🟡 부분 가능 | 얼굴이 어두워져 landmark 정확도 저하. 히스토그램 평활화로 보완 가능하나 완벽하지 않음 |

---

## 착용 변수

| 조건 | 가능 여부 | 비고 |
|------|----------|------|
| 맨얼굴 | ✅ 완전 가능 | 기본 조건 |
| 안경 | 🟡 부분 가능 | 안경 프레임·렌즈 반사가 눈 crop 이미지에 포함됨. EAR 수치가 낮아지는 경향. CNN 학습 데이터에 반드시 포함시켜야 일반화 가능 |
| 마스크 | 🔴 어려움 | 마스크는 코·입 영역이라 눈 랜드마크 자체는 영향 없음. 그러나 전체 얼굴 감지 신뢰도가 떨어져 `None` 반환 빈도 증가. 실제 테스트 필요 |

---

## 행동

| 조건 | 가능 여부 | 비고 |
|------|----------|------|
| 정상 응시 | ✅ 완전 가능 | — |
| 의도적 눈 감김 | ✅ 완전 가능 | EAR 기반 자동 라벨링 가능 (`is_closed=True/False`) |
| 자연스러운 점멸 | 🟡 가능하나 라벨링 어려움 | 점멸은 100~150ms (3~4프레임). 5프레임 이동평균 때문에 경계가 모호해짐 → 자동 라벨링 오류 가능성 있음 |
| 하품 | 🟡 수집은 가능, 활용 제한 | 눈 crop 수집 자체는 됨. 하품 중 눈 상태는 "반쯤 감김"으로 open/closed 이분법 라벨링 어려움 |

---

## 각도

| 조건 | 가능 여부 | 비고 |
|------|----------|------|
| 정면 | ✅ 완전 가능 | — |
| 좌우 30도 | 🟡 가능 | MediaPipe는 약 ±45도까지 허용. 30도는 범위 안이지만 한쪽 눈이 부분적으로 가려져 crop 품질 저하 가능. EAR 계산은 더 부정확해짐 |

---

## 라벨링 자동화

수집 스크립트에서 EAR 기반 자동 라벨링이 기술적으로 가능합니다.

```
눈 감김 세션 촬영 → EAR < threshold → closed/ 폴더 자동 저장
정상 응시 세션 촬영 → EAR > threshold → open/ 폴더 자동 저장
```

단 경계 구간(점멸 순간)은 오라벨링 가능성이 있어 수동 검수 필요.

## 최종 판단

| 항목 | 판단 |
|------|------|
| 수집 코드 구현 | ✅ 가능. `eye_extractor.py` 그대로 활용 |
| 자동 라벨링 | ✅ 가능. EAR 임계값 기반 |
| 어두움·역광 조건 | 🟡 CLAHE 전처리 추가하면 가능 |
| 마스크 조건 | 🔴 실제 해봐야 알 수 있음, 우선순위 낮춤 권장 |
| 하품 라벨링 | 🔴 open/closed 이분법 적용 불가, 별도 처리 필요 |

**핵심 조건(형광등/어두움 × 맨얼굴/안경 × 정상응시/눈감김 × 정면/30도)은 기술적으로 완전히 구현 가능.**
역광·마스크·하품은 추가 처리가 필요하거나 생략 권장.
